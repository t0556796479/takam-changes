# מה השתנה בהוראות תכ"ם

מערכת שמראה **מה השתנה** בין מהדורות של הוראות תכ"ם, מאפשרת **לקרוא הוראה בדפדפן** בלי להוריד קובץ Word, ומסמנת לכל משתמש **מה התחדש מאז הביקור הקודם** בנושאים שבחר.

> סרטון הדגמה: _(קישור יתווסף)_

---

## חלק א׳: הבעיה והפתרון

### הבעיה
אתר [הוראות תכ"ם](https://takam.mof.gov.il) הוא המקור המחייב לנהלים כספיים ומנהליים במשרדי הממשלה. המשתמשים העיקריים הם חשבים, אנשי רכש ומנהלי רכב ושכר, שחוזרים לאותן הוראות שוב ושוב. בסקירה של האתר נמצאו שלוש בעיות:

1. **אין דרך לדעת מה השתנה.** להוראות יש מהדורות רבות (למשל 7.3.3 נמצאת במהדורה 18), אבל כדי להבין מה השתנה צריך להוריד שני קבצי Word ולהשוות אותם בעין. בהוראה של 50 עד 130 פסקאות, שינוי של משפט אחד נעלם בקלות.
2. **אין קריאה באתר.** תוכן ההוראה זמין רק כקובץ להורדה.
3. **הרשמה לעדכונים אומרת *שמשהו* השתנה, ולא *מה*.**

דוגמה מהמדגם: במהדורה 5 של הוראה 11.4.4 (רכב איגום), רוב השינויים הם ניסוח בלבד. אבל בתוך פסקה קיימת נוסף המשפט *"עובד המוגדר בתפקידו כנהג, זכאי להשתמש ברכב ממשלתי בתפקיד ללא הגבלה"*, לעומת מגבלה של 7 ימים בחודש. קורא אנושי יפספס את זה בקלות.

### הפתרון
- **פיד "מה השתנה":** עדכונים מהחדש לישן, עם תמצית לכל עדכון ומספר הפסקאות ששונו, נוספו, הוסרו או הועברו. אפשר לסנן לפי נושא (פרק ראשי).
- **דף שינויים:** השינויים מקובצים לפי הכותרת שבה הם נמצאים, עם הדגשה ברמת מילה: <del>נמחק</del> באדום ו<ins>נוסף</ins> בירוק. פסקאות שרק הועברו ממקום למקום מקובצות בנפרד ומקופלות. שינויי פיסוק ורווחים לא מוצגים, ורק נספרים.
- **קריאה בדפדפן:** כל מהדורה מוצגת כטקסט עם כותרות.
- **"חדש מאז הביקור הקודם":** מזהה אנונימי בדפדפן, בלי התחברות. השרת שומר את הנושאים שנבחרו ואת מועד הביקור האחרון.

## ארכיטקטורה

```
data/raw/*.docx ─┐
instructions.json┘
        │   (פעם אחת, או בכל עדכון נתונים)
        ▼
  pipeline: חילוץ ← נרמול ← השוואה ← תמצית
        │
        ▼
  מסד נתונים (SQLite / PostgreSQL)
        │
        ▼
  FastAPI  :8000   /api/...
        │
        ▼
  React (Vite) :5173  ── /api מועבר ל-8000
```

**העיקרון:** ההשוואה מחושבת מראש ונשמרת, והשרת רק קורא. כך התגובה מהירה, וההשוואה הכבדה לא רצה בכל בקשה.

| רכיב | קבצים | תפקיד |
|---|---|---|
| חילוץ | `backend/app/core/extract.py` | קריאת Word לפסקאות. כותרות מזוהות לפי סגנונות המסמך של תכ"ם ("כותרת רמה 1", "סעיף רמה N" קצר), כדי שכל שינוי ישויך לכותרת שלו |
| נרמול | `backend/app/core/normalize.py` | התעלמות מניקוד, גרשיים, מקפים, פיסוק ותווי כיווניות, כדי לא לדווח על שינוי שאינו שינוי |
| השוואה | `backend/app/core/diff.py` | יישור פסקאות (difflib), התאמת "שונה" לעומת "נמחק ונוסף" (דמיון 50% ומעלה), השוואת מילים בתוך פסקה, וזיהוי פסקאות שהועברו (זהות, או דמיון 80% ומעלה) |
| תמצית | `backend/app/ai/analyzer.py` | תמצית לפי כללים. ממשק מוכן ל-Claude שיסווג "מהותי או ניסוחי" (ראו חלק ג׳) |
| עיבוד | `backend/app/pipeline.py` | מריץ את כל השלבים ושומר. מדלג על קובץ פגום או חסר, ואפשר להריץ שוב בלי כפילויות |
| מסד | `backend/app/models.py` | `instructions`, `editions` (כולל הטקסט), `change_sets`, `changes`, `visitors`, `subscriptions` |
| API | `backend/app/api/` | FastAPI: `/changes`, `/chapters`, `/instructions/{code}`, `/instructions/{code}/changes/{v}`, `/instructions/{code}/editions/{v}`, `/visitors/...`, `/health` |
| ממשק | `frontend/src/` | React: פיד, דף שינויים, קריאת מהדורה |

**ההשוואה היא לוגיקה בלבד, בלי AI.** התוצאה דטרמיניסטית, ניתנת לבדיקה ולא עולה כסף.

## חלק ב׳: הרצה

**דרישות:** Python 3.12, Node.js 20 ומעלה.

### 1. שרת ועיבוד הנתונים
```powershell
cd backend
python -m venv .venv
.venv\Scripts\activate            # ב-Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt
copy ..\.env.example ..\.env      # ב-Linux/Mac: cp ../.env.example ../.env

python -m app.pipeline            # מעבד את data/ ושומר ל-backend/takam.db
uvicorn app.main:app --reload     # API על http://localhost:8000
```

### 2. ממשק (בטרמינל נוסף)
```powershell
cd frontend
npm install
npm run dev                       # http://localhost:5173
```

### הגדרות (`.env`)
כל ההגדרות נמצאות בקובץ `.env`, מחוץ לקוד, ו-`.env` לא נכנס ל-Git. הקובץ `.env.example` הוא תבנית בלי סודות.

| משתנה | ברירת מחדל | משמעות |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./takam.db` | כתובת מסד הנתונים. למעבר ל-PostgreSQL מחליפים רק את השורה הזאת (ומתקינים `psycopg`), בלי שינוי קוד |
| `AI_PROVIDER` | `none` | `anthropic` מפעיל את Claude |
| `ANTHROPIC_API_KEY` | ריק | נדרש רק כש-AI מופעל |
| `CORS_ORIGINS` | `http://localhost:5173` | כתובות הממשק שמורשות לפנות ל-API |

### נתונים
מדגם של 13 הוראות (25 קבצים) משלושה פרקים, שהורד ידנית מהאתר. פירוט וקריטריון הבחירה נמצאים ב-[`data/SAMPLE.md`](data/SAMPLE.md).

כלי עזר לטרמינל: `python -m app.show` לתמצית של כל ההוראות, `python -m app.show 7.3.3` לפירוט הוראה אחת.

## בדיקות

```powershell
cd backend
pytest        # 45 בדיקות, כמה שניות
```

הבדיקות לא תלויות ברשת. מסמכי Word לבדיקה נוצרים בזמן הריצה, וה-API נבדק מול מסד זמני בזיכרון. בדיקה אחת רצה על מסמך אמיתי מהמדגם (11.4.4), ומוודאת שהמערכת מוצאת את התוספת המהותית שתוארה למעלה.

**מקרי קצה עיקריים:**

| מקרה | התנהגות |
|---|---|
| הוראה עם מהדורה אחת (11.4.1) | אין השוואה. דף ההוראה מציג "אין מול מה להשוות" |
| קובץ פגום או חסר | המהדורה מדולגת ונרשמת אזהרה בלוג, ושאר ההוראות ממשיכות |
| מהדורות זהות, או שינוי בפיסוק בלבד | "לא נמצאו שינויים בתוכן". שינויי פיסוק רק נספרים |
| פסקה שהועברה | מסומנת "הועבר" ולא "נמחק ונוסף" |
| הרצה חוזרת של העיבוד | ללא כפילויות |

**תרחישים ידניים בממשק:**
1. בוחרים נושא "11 · רכב ממשלתי", והפיד מציג רק את פרק 11. אחרי רענון הבחירה נשמרת.
2. משנים את התאריך ל-01/07/2026, ויותר עדכונים מסומנים "חדש". בוחרים "רק חדשים", ומוצגים רק הם.
3. נכנסים ל-11.4.4: בפסקה "שימוש ברכב" מודגש בירוק המשפט שנוסף. משם לוחצים "מהדורה 5" וקוראים את ההוראה המלאה.
4. עוצרים את השרת ומרעננים: מופיעה הודעת שגיאה ברורה ולא מסך ריק.

## חלק ג׳: החלטות הנדסיות ותפעול

### החלטות ומה לא מומש

- **בלי AI בתוצר, עם ממשק מוכן.** ההשוואה עצמה לא צריכה AI. הערך של AI הוא בסיווג **מהותי או ניסוחי** ובתמצית במילים. המימוש (`ClaudeAnalyzer`) קיים ונבדק עם לקוח מדומה, כולל פלט JSON לפי סכמה וחזרה אוטומטית לכללים בכל שגיאה. הוא כבוי כברירת מחדל כדי שהפרויקט ירוץ בלי מפתח בתשלום. מפעילים אותו בשורה אחת ב-`.env`.
- **מדגם ידני ולא סקריפט איסוף.** ל-13 הוראות סקריפט היה מסובך מהנדרש. בנוסף, ה-API שהאתר משתמש בו אינו רשמי ועלול להשתנות.
- **טבלאות לא נכללות בהשוואה.** זו מגבלה ידועה, ומסך הקריאה מציין אותה.
- **מספור סעיפים:** המספרים (1.2.3) נוצרים אוטומטית ב-Word ולא נמצאים בטקסט, ולכן שינוי משויך לכותרת ולא למספר סעיף. אותה סיבה גורמת לכך ששינוי של אות נספח (נספח א׳ שהפך לנספח ב׳) מוצג כ"שונה".
- **"חדש" לפי תאריך התחולה** של המהדורה, ולא לפי מועד הפרסום באתר. במערכת אמיתית שומרים גם מתי המהדורה זוהתה לראשונה.
- **מבקר אנונימי** (מזהה בדפדפן) ולא הזדהות. דפדפן אחר נחשב מבקר חדש.
- **לא מומש:** בדיקות לממשק React, התראות במייל.

**השינוי המשמעותי ביותר לתחזוקה וסקייל:** החלפת ההרצה הידנית ב**סנכרון מתוזמן**. ג׳וב יומי ימשוך את רשימת ההוראות, יזהה מהדורות חדשות, יוריד רק אותן ויעבד רק את ההוראות שהשתנו. היום העיבוד בונה מחדש כל הוראה. בנוסף: מעבר ל-PostgreSQL, ניהול שינויי סכמה עם Alembic, שמירת הקבצים המקוריים באחסון קבצים, והזדהות ארגונית (SSO) במקום מזהה אנונימי.

### פריסה ותפעול בסביבה ארגונית

**מה נדרש לפריסה אוטומטית:**
- Dockerfile לשרת ולממשק (הממשק נבנה ל-`dist` ומוגש מ-Nginx, שמעביר את `/api` לשרת), ו-docker-compose עם PostgreSQL.
- Pipeline של CI/CD (למשל GitHub Actions): הרצת `pytest` ו-`npm run build` על כל שינוי, בניית images, ופריסה לסביבת בדיקות ואחר כך לייצור, רק אם הבדיקות עברו.
- סודות (מפתח API, סיסמת מסד) מנוהלים במנהל סודות של הסביבה, ולא בקוד או ב-image. הקוד כבר קורא הכול ממשתני סביבה.
- מיגרציות של מסד הנתונים רצות כשלב מפורש בפריסה, לפני עליית הגרסה החדשה.

**איך מוודאים שהפריסה תקינה:**
- `GET /api/health` מחזיר `status: ok` ואת מספר ההוראות במסד. כך מזהים גם שרת שעלה מול מסד ריק או שגוי, ולא רק שרת שלא עלה. משמש כ-readiness probe, והפריסה נעצרת אם הוא נכשל.
- Smoke test אחרי פריסה: קריאה ל-`/api/changes` ולדף הראשי, ובדיקה שחוזרים נתונים.
- ניטור שוטף: שיעור שגיאות 5xx וזמני תגובה, ו"גיל" הסנכרון האחרון שהצליח.

**תרחיש כשל משמעותי: האתר שינה את מבנה המסמכים או את ה-API**
- *מה קורה:* הסנכרון ממשיך "להצליח", אבל החילוץ מחזיר מעט פסקאות או בלי כותרות, וההשוואה מדווחת שכל ההוראה "נמחקה ונכתבה מחדש". המשתמשים מקבלים שינויים מזויפים.
- *איך מזהים:* הלוג של ה-pipeline כבר רושם לכל הוראה כמה שינויים נמצאו ומדלג על קבצים שלא נקראים. בייצור מוסיפים התראה על חריגה: הוראה שבה מעל 80% מהפסקאות השתנו, או ירידה חדה במספר הפסקאות שחולצו. על ריצה כזו נעצר הפרסום ונשלחת התראה.
- *איך מאבחנים:* משווים את הקובץ החדש לקודם (סגנונות, מבנה), ומריצים את `python -m app.show <code>` ואת בדיקת המסמך האמיתי מול הקובץ החדש. בגלל שהעיבוד חוזר על עצמו בלי כפילויות, אחרי תיקון מריצים שוב רק את ההוראות שנפגעו.
- *כשל נוסף, כשה-AI מופעל:* כשהשירות לא זמין, המערכת חוזרת אוטומטית לכללים ומסמנת את התוצאה `rules (AI fallback)`. ספירה של הסימון הזה בניטור מראה מתי ה-AI לא עובד.
